3 · Connect other systems

What Maia knows can flow into every other tool

MCP is an open standard, so one assistant can read from Maia and, when those tools are connected too, write to chat, tickets, sheets, docs and email in the same conversation. The Maia server supplies the data. Each other tool brings its own connection and permissions.

●

Each Maia connection uses one region and one set of API credentials. You can add more than one, for example a sandbox and a production account, and the assistant can use both in one conversation.

4 · Know the limits

Powerful, and clear about its edges

What the MCP can't show, and what it can change, both matter when you set expectations.

Not available through the MCP

  • The contents of a pipeline file, including components, SQL and canvas notes. Descriptions and file lists are available.
  • Who has access to a project and which role they hold.
  • A list of git branches. Branches appear through deployed versions and Maia Team tasks.
  • Audit events older than 90 days, or filtered by person or project.
  • Lineage looked up by table name. It is searched by time window.
  • Editing a pipeline in the designer or on a branch. Maia Team tasks do that work.

What write tools can do

  • Publish and promote versions, including to production environments, and start pipeline runs.
  • Create, change or delete schedules, projects, environments, runners and secret references. Deleting a project, environment or secret cannot be undone.
  • Rotate a runner’s secret and change which projects a runner can serve.
  • Start Maia Team tasks that can write and commit to a branch, working under the identity of the credential’s user.

Working safely

  • Results depend on the API credentials you connect with. Use a credential whose role matches what your audience should see.
  • Write tools are off by default. Turn them on only when you need them, and ask your AI client to confirm each one.
  • Read tools can still reveal sensitive details, such as people’s emails in audit events, pipeline names in credit data, and customer names in branch names and task descriptions.
  • Avoid typing secrets into the conversation. A secret reference created through the assistant passes its value through the chat.
  • Plan mode only produces a plan. Act mode writes changes on a separate branch for review.
  • Many changes appear in the audit log, and new event types are still being added, so do not treat it as complete. The docs describe a channel tag for MCP activity, but we did not see it populated, so check before relying on it.
