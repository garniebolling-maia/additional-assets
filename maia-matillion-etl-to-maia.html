At a glance

Familiar concepts, a new way to run them

Your Matillion ETL experience carries over. The building blocks are recognizable, the migration is guided, and Maia adds new ways to build and run the work.

  1. What carries over

    Jobs, shared jobs, schedules, API query profiles, variables and secret references can be brought across with the Upgrade Assistant.

  2. What changes

    Projects are Git-backed, releases are published artifacts, schedules run those artifacts, and the runner is hosted by Matillion or deployed in your cloud.

  3. What’s new

    Maia Team builds and explains pipelines from plain language, and context files carry your standards into every build.

Step 1 of 7

Map what you know

Most of what you know carries over. Orchestration and transformation jobs become orchestration and transformation pipelines. Shared jobs become shared pipelines that can be reused across projects, and API query profiles become custom connectors.

Maia also adds test pipelines, which verify that a pipeline behaves as expected before you deploy it.

Step 2 of 7

Choose a deployment and set up a project

Pick Full SaaS, where Matillion hosts the runner so there’s no infrastructure to install or upgrade, or Hybrid SaaS, where you deploy the runner in your own cloud for more control over networking, secrets and drivers. You choose per project.

Then create a Maia project, an environment that connects it to your cloud data warehouse, and a branch to receive the migrated pipelines.

Maia capabilities

Full SaaSHybrid SaaSEnvironmentsGit-backed project

Create a new test project instead of importing straight into production. Hybrid SaaS is available on specific plans.

Step 3 of 7

Scan with the Upgrade Assistant

The Upgrade Assistant connects from Maia to the APIs of your Matillion ETL instance and reads the structure of one project: jobs and components, shared job details, schedules, task history, the list of JDBC drivers and secret references. It never reads your data or secret values.

Then choose what to migrate: individual jobs, shared jobs or schedules. Dependencies such as sub-jobs, API query profiles and shared jobs are identified for you.

Maia capabilities

Upgrade AssistantDependency selectionSecret references

You need a Matillion ETL user with Server Admin, API, Global Project Admin and All Global Access permissions.

Step 4 of 7

Migrate and convert

Migrate your selection with or without its dependencies, and come back for more at any time. Options handle the common differences: convert Python 2 scripts to Python 3, convert Python Script components to Python Pushdown (Snowflake projects) or Script Pushdown, convert Bash Script components to Script Pushdown, and predict job dependencies that use variables in their names.

Shared jobs arrive as shared pipelines, API query profiles as custom connectors, and secret references come across too.

Maia capabilities

Python 2 to 3Pushdown conversionsShared pipelines

Original and converted scripts are both kept under .matillion/migration so you can compare them. Matillion can’t guarantee a converted script works, so review and test each one.

Step 5 of 7

Validate the results

Treat migrated pipelines as a draft to verify. Ask Maia Team to /explain a pipeline and /document it, validate pipelines against your warehouse, and sample data at each component to compare with what your existing jobs produce.

Add test pipelines to confirm behavior before deployment.

Maia capabilities

/explain and /documentValidate and sample dataTest pipelines

Migrate a small slice first and compare its output with the Matillion ETL job before you move the rest.

Step 6 of 7

Release and run

Commit and push to a branch, then publish an artifact: an immutable package built from a specific commit. Schedules run the latest version of an artifact or a specific one, so what runs in production is exactly what you released.

Promote through development, staging and production environments, and use notifications and run history to monitor each run.

Maia capabilities

ArtifactsSchedulesNotificationsRun historyLineage

In non-production projects, choose “Always use latest” so migrated schedules update as new versions publish. Lineage is available on specific Maia plans.

Step 7 of 7

Improve with Maia Team

Once your workloads run, use Maia Team to refactor and optimize what you migrated and to build new pipelines from plain-language requests. Capture your naming and data standards in context files so new work follows them.

Assign larger jobs as tasks in Mission Control, and use plan mode to review a plan before anything changes.

Both give you the same Maia platform and Designer. The difference is where the runner lives and who manages it. You choose per project, and a project can’t switch models later.

Common questions

What Matillion ETL teams ask before they start

Do we have to migrate everything at once?

No. The Upgrade Assistant works on one project at a time, and within a project you choose individual jobs, shared jobs or schedules, with or without their dependencies. You can run it again later, and send different projects or jobs to different Maia projects.

Does the Upgrade Assistant copy our data or secrets?

No. It reads project structure, jobs and components, shared job details, schedules, task history, the list of JDBC drivers and secret references. It never reads your data or the values of your secrets. Passwords that point to AWS Secrets Manager get a new reference to the same secret, and other passwords get placeholder references for you to complete.

What do we need before we run it?

The URL of your Matillion ETL instance, and a user there with Server Admin, API, Global Project Admin and All Global Access permissions. On the Maia side you need a project with an environment and a branch to receive the pipelines. A new test project is the safest place to start.

What happens to our Python scripts?

Maia supports Python 3 only. The Upgrade Assistant can convert Python 2 scripts, and both the original and converted versions are stored so you can compare them. You should review and test every converted script. Python Script components can also be converted to Python Pushdown for Snowflake projects, or to Script Pushdown.

Can someone help with the migration?

There are two routes. Self serve follows the migration guides in the Matillion ETL documentation. Assisted means support from Matillion or a Matillion partner, and your Matillion Account Manager can set that up. The guides are migration considerations, prerequisites and process.

Do we have to use Maia Team?

No. You can build and edit pipelines yourself in Designer, and migration works without Maia Team. It’s on by default, and account admins can turn it off.

Are all of these capabilities on every plan?

Not all of them. For example, Hybrid SaaS and lineage are available on specific Maia plans. Check with your Matillion team for what your plan includes.
